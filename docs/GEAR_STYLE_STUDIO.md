# Gear Style Studio

The candidate collection contains 30 original designs: three per preview slot, across degen, crypto, tech, meme and original aetherpunk themes. It includes independent Pants and Footwear slots. The source preview is `/gear-studio`. The Bazaar hero, three outfit cards and six lineage examples use the same fitted renderer. Bazaar item-art links open the full-screen collectible viewer.

## Art and rendering

- `packages/gear-catalog/collections/style-studio-v1.source.json` records design intent, target rectangles, orientation and per-item masks.
- `packages/gear-catalog/collections/level10-fit-rig-v2.json` records the adult pose, neck/waist/grip anchors, protected contours and foreground skin masks. V1 is superseded.
- `packages/visual-engine/src/fit-rig.mjs` validates the rig and resolves mirrored anchors to canvas positions. The build checks tool proportions.
- `packages/visual-engine/src/style-studio.mjs` defines slot selection, bookmark links, draw order and complete-image loading. Browser rendering uses a generated byte-identical copy at `public/gear-style-studio/model.mjs`.
- `apps/hatchery-web/public/gear-style-studio/v1/catalog.json` records every asset hash, size, wearable placement, six canonical base references, three presets and six Bazaar showcases.

Each item has a 1024-square standalone `.item.webp`, a small `.thumb.webp`, and a separate 1024-square `.wearable.webp`. Body and pants also have a `.rear.webp`. Standalone art keeps the complete object and fills its own frame. Front and rear surfaces partition one projection: neckline/armhole lining and the rear waistband move behind the Pet, while visible straps, fabric and belt stay in front. Full artwork does not inherit these cutouts. Eyewear retains its separate forehead/temple masks.

Body wearables are mirrored and registered to the neck anchor, with a 291×255 target at (377,470). Pants attach to the waist landmark and widen toward the splayed legs. Rear contours are authored in each item's fitted reference space; their reference transform follows subsequent anchor/scale adjustments. Anatomical masks remain fixed to the Pet. Each shoe uses an independently cropped and placed projection.

All three tools are mirrored and registered by their individual handle origin to the same grip landmark, rather than positioned by their outer rectangle. Targets retain the alpha-trimmed source aspect ratio within 2%; the previous narrow vertical stretch is removed. A lossless lineage-specific projection of the original fingers draws above the tool. An equivalent original-skin layer restores the bent arm above clothing. These are original Pet pixels, not painted replacement hands.

The six original level-10 references are copied byte-for-byte from the existing public V5.1.1 assets and checked against the canonical catalog's runtime SHA-256. A separately hashed base projection suppresses toes when closed footwear is selected, so bare feet cannot protrude through the shoes. Barefoot looks use the unchanged original. No base repainting or canonical catalog edits are involved. This fit rig supports only the fixed level-10 website pose; animation and different poses need separate rigs.

The candidate plane order is habitat, back, body rear, pants rear, Pet, footwear, pants front, body front, Pet arm foreground, face, head, tool, Pet finger foreground, charm, companion. Missing pose, depth or required foreground assets fail the render instead of falling back to flat overlays. Studio's expandable **See how the gear fits** section shows rear/front/worn views for all nine body, pants and tool designs, with an optional attachment-point guide. It does not change the selected outfit or exported PNG.

This does not change the canonical V5 renderer. The candidate collection has no token IDs, balances, stats, prices, contracts or equip authority. A bookmarked outfit is an art selection, not a verified loadout. The canonical protocol still has eight slots; [the V2 proposal](architecture/gear-slots-v2.md) records the real-equipment integration needed for Pants and Footwear.

## Rebuilding and review

Use the pinned Node/npm environment and Sharp dependency:

```sh
node scripts/build-style-studio.mjs --art <original-PNG-directory> --bases <canonical-public-asset-directory> --review <review-output-directory>
node scripts/review-style-studio.mjs --out <review-output-directory>
npm run test:style
npm run check
```

The original generated PNGs are retained in the user's workspace deliverables, outside Git. They are named by design ID. The prompt set is [style-studio-prompts.json](reviews/style-studio-prompts.json); all 30 designs used the built-in image generation tool with the canonical adult as a style/proportion reference. The committed WebP artifacts are sufficient to review and integrate the candidate UI; regeneration also requires the retained original PNGs. Do not silently regenerate released artwork.

The review script produces 180 item/lineage composites and 18 complete outfits, with ten slot contact sheets. The review record is [style-studio-fit.md](reviews/style-studio-fit.md). Tests verify catalog boundaries, front/rear/foreground hashes, alpha, anatomical regions, mirror-aware anchors, tool proportions, original finger pixels, missing depth/pose rejection, independent shoes, URLs and Bazaar/Studio parity. These checks do not establish artistic approval, ownership or chain validity.
